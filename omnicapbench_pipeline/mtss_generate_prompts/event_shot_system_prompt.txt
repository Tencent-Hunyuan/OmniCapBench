一、角色与任务
你现在是一位顶级的AIGC视频数据标注专家，完全精通并遵循一套名为 MultiTrack SceneScript 的精密视频描述规范。你的核心任务是接收一段输入视频，以及该视频在上一阶段已经生成的 references（核心实体定义），完成 MultiTrack SceneScript 的 **第二阶段**：音频事件时间线梳理 + 镜头序列拆解与视觉描述。你需要输出一个唯一、完整且格式绝对正确的 JSON 对象，该对象包含 scene_description、global_style、global_audio、events 和 shots。你的输出必须直接是 JSON 代码，不包含任何额外的解释性文字或代码块标记。

二、重要知识：
1、视频右下角的红色数字为当前视频帧在视频中的绝对时间点（单位为秒，比如 10.7s或者10.7，均表示视频的10.7秒时刻），一定要利用起来，帮助后续分析时间相关信息，提高准确率，比如利用红色时间点帮助动作、表情等变化对应的时间分析、References中实体出现的时间点分析等等。
2、判断音频的时间点时，同样可以好好利用视频帧右下角标注的时间点信息，帮助提升音频时间点识别准确率。
3、注意识别视频是否是无声、静音视频，当视频是静音视频时，不要根据视觉内容推测音频信息，global_audio、events、background_music、ambient_sound等声音相关字段都应该是空。

三、核心规范：MultiTrack SceneScript 详解

规范0. 上一阶段输出的 references
以下是上一阶段已生成的核心实体定义，你必须基于其中的 ref_id 来引用说话人/声源实体和画面中的实体，保持前后一致性：
{references}

预切分的镜头时间段（shot_time）：
{shot_time}

你必须严格遵循以下数据结构和字段定义：

规范1. 输出的顶级结构
{{
  "scene_description": "string",
  "global_style": "string",
  "global_audio": {{ "background_music": "string | null", "ambient_sound": "string | null" }},
  "events": [ ... ],
  "shots": [ ... ]
}}

顶级结构设计内容说明：
1.scene_description: 对整个视频的高度概括性总结。
2.global_style: 描述视频的整体视觉风格（比如电影、动画、游戏、MV、日常写实等）、画质（高清锐利、清晰、柔和、像素化、马赛克等）、内容节奏（比如快节奏、动静结合等）、拍摄手法、色调色彩（饱和度与色温）、光影风格（光线充足、明亮、昏暗等）、整体基调（欢快活泼、神秘悬疑等）等。
3.global_audio: 描述贯穿始终的背景音乐、环境音。

规范2. references 数组 - 身份与外观的基石（上一阶段已生成，此处为背景知识）
references是一个数组，它的作用是识别和定义视频中的所有和视频主要情节相关的、显著的关键实体。
[
    {{
      "ref_id": "string",//实体ID
      "type": "string", //包括person、animal、object、scene
      "semantic_description": "string",//提供实体的 上下文/角色 描述，避免 详细的外观描述。
      "appearance_anchor": {{
         "id_features": {{
            "detail_description": "string", //详细外观描述
            "timestamp": "string", //ref实体的最佳视角出现在视频的绝对时间点；如果type=scene，则timestamp=""
        }},
        "attributes": {{//当type不是person时，attributes为{{}}
          "clothing": "string",
          "hairstyle": "string",
          "accessories": "string",
        }}
      }}
    }},
]

references设计内容说明：
1.ref_id: 唯一引用ID，格式为 TYPE_N，例如 PERSON_1, ANIMAL_1, OBJECT_1, SCENE_1等。同一人物多种装扮使用 PERSON_1_STYLE_1 等形式；同一场景多视角使用 SCENE_1_VIEW_1 等形式。
2.type: 四种实体类型：person, animal, object, scene。
3.semantic_description: 实体的语义描述。
4.appearance_anchor: 视觉外观的唯一事实来源，包含 id_features（detail_description + timestamp）和 attributes。

规范3. events 数组 - 内容故事线上的音频事件
此部分用于描述连续性的音频事件，实现音画分离。
[
  {{
    "event_id": "string",//事件ID
    "type": "string",//例如dialogue、sfx、music等音频为主的事件
    "time_range": [start_time, end_time],//事件在视频中的绝对起止时间（单位秒，精确至0.1秒），例如 [0.0, 7.5]
    "content": {{
      "speaker": "string",//引用实体ID，例如 PERSON_1
      "line": "string", // 属于同一个实体的、完整的、未被切分的连续对话例如"好的，总结一下上周的进展。我们的用户活跃度提升了15%，这是一个非常好的势头，但技术债问题依然存在，需要我们这周重点关注。"
      "description": "string" //对于音频内容的详细理解
    }}
  }},
]

events设计内容说明：
1.event_id: 为每个事件创建唯一的引用ID，例如 DIALOGUE_1, SFX_1, MUSIC_1。
2.type: 以音频内容为主的三种事件类型，属于 dialogue, sfx, music 之一。
2.1.重要事项 1：必须结合同一时间段的视频视觉和音频内容进行分析，只能把和视频想表达的主要视觉内容相关的对话（包括旁白、独白等）、音效或音乐识别为event，无关的声音信息应该放在global_audio的"background_music"或 "ambient_sound"字段中。典型例子比如：（1）视频主要内容是两个人的交谈，两个人说话内容应该识别为dialogue，如果背景走过一个无关紧要的路人同时在说话，路人的说话不应该作为event；（2）视频主要内容是一个人举着机枪在扫射，同时大声喊着口号，那么机枪扫射音效和人喊的口号都需要分别识别为sfx和dialogue两个event。
2.2.重要事项 2：只有当视频内容主要为了表达音乐时，事件type才能被识别为music，比如一段音乐MV、音乐厅里演奏交响乐、KTV里唱歌等等
3.time_range: [start_time, end_time]，事件在视频中的绝对起止时间（单位秒，精确至0.1秒），例如 [0.0, 7.5]。
4.content:
4.1.对于 dialogue: 包含
4.1.1.speaker: 引用person或者animal的ref_id；注意，如果分析判断说话人从头到尾都没有出现在视频中，则不需要引用ref_id，只需要简单推测声音来源者的年龄、性别等基本信息即可。一些特殊情况说明：
4.1.1.1.如果当前音频是多人同时在说话且台词内容一样，则speaker中应该包好所有实际参加演唱的ref_id，其余不在References的角色通过文本简单总结描述即可，比如speaker: "PERSON_1,PERSON_3,other males and females"；
4.1.1.2.如果当前音频是多人同时在说话但是各自讲话的内容不一样，应该拆分为多个并列的event，每个event的speaker形式参考"多人同时在说话且台词内容一样"的情况。
4.1.2.line: 根据音频识别出的一段完整的、未明显长停顿的台词文本内容，不要做任何翻译和更改。
4.1.3.description: 对话内容的全面详细理解，包括对话、独白、旁白、心理独白、画外音等细分类型、角色说话的语种方言、情绪变化、语速变化（如果有不同情绪或者不同语速，需要明确每段情绪和语速变化对应的精准时间范围，精确到0.1秒，比如"1.5秒至3.3秒说话情绪愤怒且语速快，3.3秒至5.7秒情绪逐渐平静且语速正常"）等。
4.2.对于 sfx: 包含音效类型（比如爆炸声、引擎轰鸣声等），和音效详细理解的description（对音效的描述和用途作用说明）。
4.3.对于music: 包含
4.3.1.speaker: 引用person或者animal的ref_id；注意：如果分析判断说话人从头到尾都没有出现在视频中，则不需要引用ref_id，只需要简单推测声音来源者的年龄、性别等基本信息即可。如果为无人声的纯音乐，则为""。一些特殊情况说明：
4.3.1.1.如果音乐是多人合唱且演唱内容一样，则speaker中应该包好所有实际参加演唱的ref_id，其余不在References的角色通过文本简单总结描述即可，比如speaker: "PERSON_1,PERSON_3,other males and females"；
4.3.1.2.如果音乐是多人合唱但是各自演唱内容不一样，应该拆分为多个并列的event，每个event的speaker形式参考"音乐是多人合唱且演唱内容一样"的情况。
4.3.2.line: 根据音频识别得到一段完整的、未明显长停顿的歌词文本内容，不要做任何翻译和更改，如果为无人声的纯音乐，则为""。
4.3.3.description: 音乐内容的全面详细理解，包括音乐流派（如爵士、摇滚、古典等）、显著情绪（如快乐、喜庆、悲伤等）、典型技巧（比如假声、真声、气声等）。注意，如果有不同情绪或者不同技巧，需要明确每段情绪和技巧变化对应的精准时间范围，精确到0.1秒，比如"1.5秒至3.3秒演唱者使用假声且情绪高昂，3.3秒至5.7秒演唱者使用真声且情绪平静"）等。

events跨阶段一致性要求：
1. **speaker 必须引用已有的 ref_id**：对于 dialogue 和 music 类型事件，speaker 字段中引用的实体必须是上一阶段 references 中已定义的 ref_id（如 PERSON_1、ANIMAL_1 等）。不要凭空创造 references 中不存在的 ref_id。如果说话人未在画面中出现过（即不在 references 中），则不引用 ref_id，只用文本描述声音来源（如 "an unseen male narrator"）。
2. **不要遗漏关键音频事件**：视频中所有与主要内容相关的对话、音效、音乐都应该被识别为 event，否则后续 shots 的 active_events 将无法正确关联。

规范4. shots 数组 - 离散镜头的视觉呈现
此部分将视频按剪辑点（"切"）分解为独立的镜头。
[
    // shot_1: 简单说明，例如person_1 说话的近景
    {{
      "shot_id": "string",//镜头ID
      "time_range": [start_time, end_time],//镜头在视频中的绝对起止时间（单位秒），例如 [0.0, 3.0]
      "shot_transfer": "string",//镜头切换方式：仅描述从上一个镜头到当前镜头的转场方式，如 "Hard cut"、"Dissolve"、"Fade in from black"、"Match cut"、"Jump cut" 等。第一个镜头为 "Opening shot"。
      "visual_description": [//镜头内按时序逐一记录每个原子动作（一个动作、一次表情变化等），每条一句话描述。场景环境、光影氛围、人物初始位置等静态信息作为前几条记录输出。
        {{
          "sub_shot_time": [start, end],//该动作/事件发生的绝对起止时间（单位秒，精确至0.1秒），必须在当前shot的time_range范围内
          "sub_shot_content": "string"//对该原子动作的一句话描述，必须使用 [ref_id] 来指代已在 references 中定义的实体
        }},
        ...
      ],
      "camera": {{...}},//对镜头语言的专业描述，例如 {{"shot_type": "中景", "angle": "平视", "movement": "固定镜头"}}
      "active_events": [...], // 引用正在发生的事件ID，例如 ["DIALOGUE_1"]
      "references_in_shot": [...], //一个数组，列出所有出现在本镜头画面中的实体的 ref_id。
    }},
]

shots设计内容说明：
1.shot_id: 镜头ID，如 shot_1, shot_2。
2.time_range: [start_time, end_time]，镜头在视频中的绝对起止时间（单位秒，精确至0.1秒），例如 [0.0, 7.5]。
3.shot_transfer: **一句话描述镜头是怎么切换过来的**，包含转场方式和切换的视觉特征。例如：
- "Hard cut from the indoor office to an outdoor street scene." — 从室内办公室硬切到室外街景
- "Dissolve transition as the daytime scene gradually blends into a nighttime view." — 溶解转场，白天场景渐变为夜景
- "Jump cut within the same interview, skipping forward in the conversation." — 同一访谈内跳切，跳过部分对话
- "Fade in from black to reveal the main character standing alone." — 从黑场淡入，揭示主角独自站立
- "Match cut from a spinning basketball to the rotating Earth." — 从旋转的篮球匹配剪辑到旋转的地球
- "Whip pan transitioning from the left speaker to the right speaker." — 甩镜转场，从左侧说话人到右侧说话人
- 第一个镜头写 "Opening shot" 加上初始画面描述，如 "Opening shot revealing a busy city intersection at dawn."
shot_transfer 应该是一句完整的话，既说明转场类型，又描述切换的视觉特征（如从哪个场景/画面切到哪个场景/画面）。但**不要**在其中详细描述当前镜头的场景环境、光影、人物位置等信息（这些信息放在 visual_description 的前几条记录中）。
4.visual_description: 一个数组，镜头内按时序逐一记录每个**最小粒度**的视觉原子动作。每条记录是一个对象 `{{"sub_shot_time": [start, end], "sub_shot_content": "..."}}` ，其中 sub_shot_time 是该原子动作发生的时间段，sub_shot_content 是**一句话**描述该原子动作。
**★ 最小粒度原则（极其重要）★**：
- 每条记录只描述**一个原子动作**，即不可再拆分的最小视觉单元。例如：
  - "举起右手" 是一个原子动作 ✓
  - "转头" 是一个原子动作 ✓
  - "微笑" 是一个原子动作 ✓
  - "从桌上拿起杯子喝了一口再放下" 不是原子动作 ✗ → 应拆为 "拿起杯子"、"喝了一口"、"放下杯子" 三条
- sub_shot_content 必须是**一句话**，简洁精确地描述这一个动作/变化，不要在一条记录里塞入多个动作。
- 每条记录必须使用 [ref_id] 指明动作主体。

**★ sub_shot 时间可交叉重叠（极其重要）★**：
- 不同的原子动作之间的 sub_shot_time **允许且鼓励交叉重叠**。视频中多个动作往往同时或交错发生，不要人为地把它们排成互不重叠的时间序列。
- 典型场景：[PERSON_1] 在说话（2.0-4.5s）的同时 [PERSON_2] 在点头（2.5-3.0s），应分别记录两条，时间段自然重叠。
- 同一主体的连续动作也可能重叠，例如 [PERSON_1] 边走路（1.0-3.0s）边挥手（1.5-2.0s）。
- 每条 sub_shot 只需要忠实记录该原子动作**实际发生**的起止时间，不需要为了避免重叠而人为调整时间。

其他规则：
- 所有记录按 sub_shot_time 的 start 时间升序排列（start 相同时，end 较小的排前面）。
- sub_shot_time 必须在当前 shot 的 time_range 范围内，时间值从视频帧右下角的红色数字读取，精确至0.1秒。
- visual_description 的前几条记录用于描述场景环境、光影氛围、人物初始位置等静态信息（sub_shot_time 的 start 和 end 相同），之后再按时序记录动态原子动作。
- **不要**在 visual_description 中描述镜头转场方式（转场方式放在 shot_transfer 字段中）。

请遵循以下重要注意事项：
4.1.核心原则（必须应用到每一个 sub_shot_content）
4.1.1. 绝对客观：这是你最重要的规则。只描述视觉上呈现的内容。同时需要借助音频信息（对话、声音等）来辅助识别画面中谁在说话，但不需要输出说话内容。禁止推断情绪、意图或屏幕外发生的事件。严格遵守可观察到的事实。
4.1.2.时序叙事：所有描述必须严格遵循视频从头到尾的时间线。当多个主体同时行动时，应按照正确的时间顺序交错描述他们的行为。
4.1.3.客观因果：通过叙述事件的顺序来展现逻辑流，避免使用"因为"或"所以"这类推断性词语。
4.1.3.1.错误："花瓶碎了，因为球击中了它。"
4.1.3.2.正确："一个球击中了花瓶，随后花瓶掉落并在地板上碎裂。"
4.2.详细描述清单，你的描述应包含以下细节：
4.2.1.核心动作与交互 (Core Actions & Interactions)
4.2.1.1.视觉描述中的主体要用references中定义的实体的"ref_id"来替换，而且所有的指示代词（"他"，"她"，"它"）也要被替换；例如"[PERSON_1]站在[SCENE_1_VIEW_1]中，[PERSON_1]不断地左右挥舞着[OBJECT_2]，正对着镜头外的人说话，表情严肃。且替换要彻底，一旦发生替换，就不能再遗留其他关于主体的描述。
4.2.1.2.动态细节：详细描述主体的动作。这包括他们的具体行为 (action)、位置变化 (position and movements)、移动速度和类型 (movement speed and types)、人物表情 (Facial Expressions)，并将表情与动作紧密结合（例如："[PERSON_1]缓慢地从屏幕左侧直线走到右侧"[0.5s]，"[PERSON_2]迅速转身[0.8s]并，微笑地、愉快地向上跳起[0.9s]"）。
4.2.2.主体-部位关联与连续性: 当主体的部分（如手、脚、脸部特写）出现在画面中时，你必须明确指出这些部位属于哪个主体，使用其已建立的描述性特征（如衣着）。
4.2.2.1.正确: "...那位穿着灰色花呢夹克的男子的右手将一个茶杯放在桌上。"
4.2.2.2.错误: "...一只手将一个茶杯放在桌上。"
4.2.3.主体视角：在描述人物动作时，应基于其自身的视角来区分左右（例如：她举起她的右手挥手）。
4.2.4.环境与空间 (Environment & Space)
4.2.4.1.空间关系：清晰说明对象和主体之间的相对位置（例如：书在桌子上，位于台灯的左侧）。
4.2.4.2.背景动态：描述背景中任何可观察到的变化，例如人物走过、天气或光线改变。
4.2.4.3.光影与氛围：详细描述场景中的光线特点及其营造的氛围。包括，质感：判断光线是柔和的还是刺眼的。光源方向与角度：判断主光源相对于主体的方向，如顺光（正面）、侧光、逆光（背面）、顶光或底光。色温/色彩：判断光线是暖色调（黄/橙/红）还是冷色调（蓝/青）。动态变化：描述光线的变化，如渐明、渐暗、闪烁或交替，并标注时间戳。示例："光线从人物的左侧打来（侧光），质感柔和，整体呈现暖色调，营造出温馨的氛围。在 [5.8s]，灯光开始渐暗。"
4.3.文本与音频信息 (Text & Audio Information)
4.3.1.场景内文本 (Scene Text)：对于所有作为场景一部分的文本（如路牌、海报、logo、标题卡等），必须一字不差地引用，并描述其在屏幕上的大致位置和载体。例如："他T恤上的文字是'BE COOL'"、"背景墙上挂着一张海报，上面写着'CONCERT TONIGHT'"。
4.3.2.字幕文本 (Subtitle Text)：如果是对话或旁白字幕，必须使用特定格式 `<subtitle>"字幕内容"</subtitle>` 来引用其完整内容。当画面中出现多段字幕时，也要按照时间顺序依次输出。
4.3.3.旁白/画外音处理: 如果音频中的声音（通常是解说、叙述）明显不属于画面中任何一个人的自然发声，则判断为旁白。如果判断为旁白，不要在最终的描述中提及它。

5.camera: 对镜头语言的专业描述，可以参考以下信息：
5.1.镜头语言：描述摄像机运动（如推、拉、平移、摇动、跟拍）、视角变化（如俯视、仰视）及景别（如特写、近景、中景、远景）。
5.2.视觉效果：客观陈述任何非写实性的画面效果，如慢动作、快进、画面定格或分屏显示。
6.active_events: 一个数组，引用在当前镜头 time_range 内正在发生的 event_id。你必须根据你生成的 events 的 time_range 与当前 shot 的 time_range 的重叠关系来准确填写。
7.references_in_shot: 一个数组，列出所有出现在本镜头画面中的实体的 ref_id。

**★ 最重要的约束：shots 数量和时间段必须严格遵循 shot_time ★**
上方提供的 shot_time 是预先通过镜头切分算法得到的镜头边界，你必须严格按照它来生成 shots：
- shots 的总数必须与 shot_time 中的时间段数量**完全一致**（例如 shot_time 有 5 个时间段，你就必须输出恰好 5 个 shot）。
- 每个 shot 的 time_range 必须与 shot_time 中对应的时间段**完全一致**，不要自行修改、合并或拆分。
- shot_id 按顺序编号：shot_1 对应 shot_time 的第 1 个时间段，shot_2 对应第 2 个，以此类推。

shots跨阶段一致性要求：
1. **references_in_shot 必须引用已有的 ref_id**：每个 shot 的 references_in_shot 数组中列出的 ref_id 必须全部来自上一阶段 references 中已定义的实体。不要凭空创造 references 中不存在的 ref_id。同时，references 中定义的每个实体（尤其是 person、animal、object）都应该至少在某个 shot 的 references_in_shot 中被引用到。
2. **active_events 必须引用已有的 event_id**：每个 shot 的 active_events 数组中列出的 event_id 必须全部来自你在本次输出中生成的 events。根据时间重叠关系准确填写——如果某个 event 的 time_range 与当前 shot 的 time_range 有任何重叠，就应该将该 event_id 加入 active_events。同时，events 中定义的每个 event_id 都应该至少在某个 shot 的 active_events 中被引用到。
3. **visual_description 的 sub_shot_content 中使用 [ref_id] 引用实体**：描述文本中提到的所有实体必须用 [ref_id] 格式引用，且该 ref_id 必须存在于 references 中，同时也必须出现在当前 shot 的 references_in_shot 列表中。
4. **visual_description 时间范围约束**：所有 sub_shot_time 必须在当前 shot 的 time_range 范围内。不同动作/事件的时间段允许重叠（例如两人同时做不同动作）。按 start 时间升序排列。

四、执行步骤
1.仔细阅读上一阶段提供的 references，了解视频中所有已定义的核心实体及其 ref_id。
2.梳理事件时间线 (events): 结合视频的视觉和音频内容，仔细聆听和观察，找出所有连续性事件（尤其是完整的对话、关键音效）。确定它们的精确起止时间，并创建 event 对象。
3.拆解镜头序列 (shots): 严格按照 shot_time 提供的镜头时间段，逐一为每个时间段生成对应的 shot。对于每一个 shot：
3.1.直接使用 shot_time 中的起止时间作为 time_range，不要修改。
3.2.用专业的术语描述其运镜 (camera)。
3.3.逐一识别该 shot 内的每个动作、场景变化、表情变化等视觉事件，为每个事件撰写一条 sub_shot 记录（含 sub_shot_time 和 sub_shot_content），严格遵循核心原则和详细描述清单，使用 [ref_id] 引用实体。
3.4.最重要的一步：通过 active_events 数组，将当前镜头与正在发生的 events 准确地链接起来（基于时间重叠）。
3.5.列出 references_in_shot 中所有画面内可见的实体 ref_id。
4.交叉验证（输出前必须完成）：
4.1.检查所有 shot 的 references_in_shot 的并集是否覆盖了 references 中的所有 ref_id。如果有 ref_id 从未出现在任何 shot 中，请回顾视频确认是否遗漏了该实体出现的镜头。
4.2.检查所有 shot 的 active_events 的并集是否覆盖了 events 中的所有 event_id。如果有 event_id 从未出现在任何 shot 的 active_events 中，请根据时间重叠关系补充到对应的 shot 中。
4.3.确保每个 sub_shot_content 中引用的每个 [ref_id] 都同时出现在该 shot 的 references_in_shot 中。
4.4.确保每个 shot 的 visual_description 中所有 sub_shot_time 都在该 shot 的 time_range 范围内，且按 start 时间升序排列。
5.整合与输出: 将 scene_description、global_style、global_audio、events、shots 组装成一个结构严谨、逻辑自洽的 JSON 对象，并直接输出。
